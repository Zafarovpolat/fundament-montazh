# Инструкции для AI-агента и разработчика

**Перед любыми изменениями сначала прочитай целиком `docs/AI_HANDOFF.md`.** Затем прочитай относящиеся к задаче разделы `README.md`, `design/figma-reference/README.md` и, если затрагиваются переиспользуемые секции, `sections/README.md`. Сначала изучи текущую разметку, стили, поведение и тесты — не начинай с переписывания.

Приоритет: явное указание владельца в текущей задаче → эти постоянные правила → исторические заметки. Если старый README расходится с проверенной картой Figma, см. предупреждение в `docs/AI_HANDOFF.md` и индекс `design/figma-reference/README.md`.

## Постоянные правила владельца

- Делай только запрошенный объём. Не проводи несвязанный рефакторинг, не дублируй DOM-узлы, сохраняй семантику, `#projects`, действующий контент, код и стили вне согласованного объёма.
- Не придумывай текст, ссылки, цены, сроки, характеристики объектов или факты. При нехватке данных используй подтверждённые исходники либо оставь вопрос явно открытым.
- Не используй абсолютное позиционирование ради пиксельной подгонки. Согласованные исключения: thumb/ползунок и `#design .eyebrow` в gutter.
- Пины и эффекты не должны менять высоту секции. `#design` перехватывает вертикальный ввод только в пределах горизонтального рельса, направляет его по рельсу и отдаёт странице у краёв; не вызывай повторный `scrollTo` на каждом `scroll`.
- Анимация изменения размеров карточек должна оставаться плавной (геометрия grid + height) при постоянной высоте секции.
- Проверки — регрессионные гарантии, а не цель добиться искусственного pixel-perfect 1:1. Не ослабляй тесты, чтобы скрыть дефект, и не добавляй хрупкие сравнения полных скриншотов без прямой необходимости.
- Иконки бери из `assets/icons/*.svg`, обновляй спрайт через `tools/build_icon_sprite.py`; inline SVG применяй только если он прямо задан задачей.
- Порядок hero-слайдов: сначала `copy`, затем `price`.
- Cookie-плашка: CTA закреплена у нижнего края; при ширине ≤1440 px тексты и отступы адаптивно уменьшаются.
- `hero-badge` при ширине ≤1024 px остаётся одной длинной общей плашкой — не разделяй на три пилюли.
- Не сохраняй и не выводи PAT, Figma-токены, cookies, подписанные URL или иные секреты. Для Git используй только временную передачу секрета процессу/askpass; не клади его в файлы, URL remote, Git config/credentials или commit.

## Работа с репозиторием

1. До правок проверь `git status --short --branch`, текущий `HEAD` и относящиеся к задаче файлы/тесты.
2. Сохраняй небольшие, проверяемые изменения. После правок просмотри diff и запусти подходящие регрессионные тесты из `package.json`.
3. Если владелец просит push и авторизация безопасно доступна, публикуй прямо в `main`, не запускай интерактивный GitHub CLI и не создавай лишних кругов согласования. В репозитории есть `tools/push-main.sh`; токен передаётся ему только через временную переменную `GITHUB_TOKEN`. Если авторизация действительно недоступна, честно сообщи об этом и не утверждай, что push выполнен.
4. Не помещай токены и подписанные Figma URL даже в отчёт, диагностические файлы или фикстуры.
