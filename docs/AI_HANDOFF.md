# Контекст проекта и handoff для следующего AI

**Срез контекста: 2026-10-08. Прочитать целиком до начала работы.** Это не стенограмма чата, а проверенная выжимка договорённостей, архитектуры, решений и источников истины. Постоянные краткие правила также находятся в корневом `AGENTS.md`.

## Как начать новую задачу

1. Прочитай `AGENTS.md` и этот файл полностью.
2. Проверь состояние ветки и незакоммиченные изменения: `git status --short --branch`, `git log -5 --oneline`.
3. Прочитай корневой `README.md` для подробной истории реализации и тестов. Для текущих Figma ID сначала открой `design/figma-reference/README.md`, затем нужный узел JSON.
4. Найди соответствующие HTML/CSS/JS и существующие тесты. Уточняй только действительно блокирующую неоднозначность; сначала проверь имеющиеся исходники и решения, чтобы не заставлять владельца повторять контекст.
5. Работай в узком объёме, запусти целевые регрессионные тесты и проверь итоговый diff.

Текущие явные инструкции владельца важнее исторических заметок. Если реализованная деталь, макет и этот документ расходятся, не угадывай: проверь актуальный узел/код и сообщи о существенном конфликте.

## Кратко о проекте

`fundament-montazh` — статический сайт компании «ФундаментМонтаж», собранный на обычных HTML, CSS и JavaScript. Фреймворка и runtime-зависимостей нет; для локального запуска используется Python static server. Маршруты: `/` — главная по Figma `1:2`/`540:662`; `/foundation.html` — сохранённая страница «Фундамент» по Figma `315:160`/`597:663`. На странице есть юридические документы, форма/диалог, квизы, карусели и адаптивные состояния.

### Основные места в коде

- `index.html` — главная; `home.css` и `home.js` — её изолированные адаптивные стили и вкладки.
- `foundation.html` — сохранённая страница «Фундамент»; `privacy.html`, `personal-data.html` — юридические страницы.
- CSS: общие `styles.css`, `interactions.css`, `figma-type.css`, `fidelity.css`, `compact.css`, `compact-type.css`, `fonts.css`, `legal.css`; изменения общих таблиц стилей проверяй на обоих маршрутах.
- JS: `app.js`, `header.js`, `hero-carousel.js`, `sliders.js`, `motion.js`, `steps-pin.js`, `layout.js`, `refinements.js`, `consent.js`; взаимодействия главной также использует `home.js`.
- `sections/projects.html` и `sections/projects.css` — извлечённый фрагмент «Готовые проекты». Порядок каскада важен: см. `sections/README.md`; не подключай самодостаточную копию `projects.css` поверх общих стилей, если задача этого не требует.
- `assets/` — изображения, шрифты и иконки; `assets/icons/figma-sources.json` документирует источники иконок.
- `design/figma-reference/` — очищенные JSON-снимки Figma; `tests/` и `tools/` — проверки и генераторы.

## Правила и предпочтения владельца

Подробный список обязателен к соблюдению; он дублирует ключевые пункты `AGENTS.md` для удобства передачи контекста.

### Объём, данные и качество

- Не дублировать элементы, не менять `#projects` или смежные стили/код вне заявленного объёма. Сохранять семантику и текущие работающие взаимодействия.
- Не выдумывать коммерческие тексты, ссылки, цены, характеристики, сроки или свойства построенных объектов. Повторяющиеся или противоречивые исходные строки не «исправлять» на догадку.
- Тесты нужны как регрессионная защита; владелец не хочет искусственных идеальных 1:1 тестов. Используй соответствующие тесты и разумные критерии поведения/геометрии, не превращай проверку в пиксельную подгонку.
- Минимизируй повторные согласования: сначала посмотри дерево, существующие решения, историю и Figma-JSON; спрашивай только о блокирующей неоднозначности.

### Геометрия, прокрутка и анимации

- Не применять `position:absolute` ради визуальной точности. Разрешённые владельцем исключения: thumb/ползунок и `#design .eyebrow` в gutter.
- Пины, параллакс и эффекты не меняют высоту секций.
- Поведение `#design`: вертикальный ввод направляется в горизонтальный рельс лишь пока указатель/страница находится в его диапазоне; у края управление возвращается вертикальной странице. Не вызывать `scrollTo` повторно при каждом событии прокрутки.
- Размер карточек анимировать плавно через геометрию grid + height; высота всей секции остаётся постоянной.
- Не добавлять к уже нативной прокрутке лишний перехват колеса и не возвращать удалённые хаки без прямой причины.

### Конкретные решения интерфейса

- В hero сначала показывается `copy`, затем `price`.
- `hero-badge` при ширине ≤1024 px — одна длинная общая плашка, не три раздельные пилюли.
- У cookie-плашки CTA закреплена снизу; при ширине ≤1440 px уменьшаются тексты и отступы.
- Иконки брать из `assets/icons/*.svg` и собирать спрайт `python3 tools/build_icon_sprite.py`; не вставлять новые inline SVG, если задача явно этого не требует.
- Сохраняй локальность изменений: не меняй тексты, ссылки, цены, состояние cookie или другие компоненты только ради визуального сходства с одним кадром.

## Актуальная карта Figma

Текущий источник карты — `design/figma-reference/README.md`; проверяй содержимое узлов, а не только их одинаковые имена вроде «Адаптив».

- `design/figma-reference/figma-pages-bundle.json` — bulk-ответ на 15 узлов, запрос `geometry=paths`; сохранены vector paths. Пакет содержит мобильную главную, mobile второй страницы, юридические и служебные экраны/компоненты.
- **Главная mobile:** `540:662`, 375 × 14233. Содержимое начинается с «10 лет строим дома», далее «Строим дома, за которые отвечаем своим именем».
- **Вторая страница «Фундамент» mobile:** `597:663`, 375 × 11906. Начинается с «За качество каждого фундамента я отвечаю своим именем».
- **Вторая страница «Фундамент» desktop:** `315:160`, 1920 × 12839, файл `figma-315-160.json`; мобильный `597:663` подтверждён совпадающими текстами и контентом.
- Новый bundle намеренно **не** содержит главный desktop `1:2`. Существующий `figma-main-tree.json` уже был в репозитории до bundle и является ранее сохранённым вариантом `Главная`, 1920 × 15969; не перезапрашивай/не подменяй им основу второй страницы.
- В bundle также есть `430:365` (политика конфиденциальности), `440:1643` (правила обработки персональных данных), `434:1410` (404), `440:1769` (спасибо за заявку), `440:1632` (cookie-баннер), `42:2` (форма), `606:1834` (mobile privacy), `606:1087` (mobile adaptive с возвратом на главную/контактами), `606:1750` (mobile спасибо), `563:563` (ещё один mobile-вариант главной), `597:1627` (компактный калькулятор), `540:856` (video block), `491:641` (шаги).

Node `315:160` называется **«Фундамент»** и относится к странице `/foundation.html`; её мобильное соответствие — `597:663`. Главная использует desktop node `1:2` и mobile node `540:662`. ## Запуск и проверки

- Локальный сервер: `npm run start` (Python на `0.0.0.0:5173`) или `python3 -m http.server 5173 --bind 0.0.0.0`.
- `npm test` — **только синтаксические проверки JS**, не полный браузерный набор.
- `npm run test:home` проверяет главную; `npm run test:browser` и прежние дополнительные регрессионные наборы адресуют сохранённую страницу «Фундамент» через `tests/site-url.cjs`.
- Браузерный smoke: `npm run test:browser`; дополнительные регрессионные наборы: `npm run test:ui`, `test:responsive`, `test:fidelity`, `test:review`, `test:sequence`, `test:path`, `test:refinements`, `test:header`, `test:compact`, `test:steps-pin`, `test:layout`, `test:review362` (через `npm run <имя>`).
- `npm run test:firefox` / `npm run test:webkit` прогоняют синтаксис и smoke в соответствующем движке. Браузерные тесты требуют установленных Playwright browser binaries.
- Выбирай тесты по затронутому поведению. Например, для horizontal pin — `test:steps-pin`, `test:layout` и нужный responsive/browser test; для consent — UI/responsive/browser. Не запускай все наборы автоматически, если изменение документационное.
- После правок: `git diff --check`, проверь точные затронутые файлы и статус; не добавляй артефакты, токены или временные манифесты.

## Git и безопасность

- Основная ветка — `main`. Когда владелец просит push и авторизация безопасно доступна, пушь сразу, без повторных кругов и без интерактивного `gh` CLI.
- `tools/push-main.sh` ожидает `GITHUB_TOKEN` в окружении процесса, использует временный askpass и отключает persistent credential helper. Передавай секрет только процессу, без сохранения в файле/remote URL/`.git-credentials`; не включай его в вывод или commit.
- Никогда не включай PAT, Figma token, `.env`, cookies, подписанные image URL или временную `figma-image-urls.json` в handoff или коммит.
- Если токен реально недоступен, не изображай успешный push: оставь подготовленный локальный коммит и коротко назови единственный блокер. Не запрашивай CLI-login, если владелец явно просит использовать безопасно доступный токен.

Обновляй этот handoff при крупных изменениях архитектуры, Figma mapping или постоянных правилах владельца. Не записывай сюда одноразовые секреты и не превращай файл в полный чат-лог.
